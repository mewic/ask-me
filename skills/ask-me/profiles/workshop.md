# Profile: Workshop — งานเอกสาร บัญชี ลูกหนี้ ใบเสนอราคา เวลา และเงินเดือน

ใช้เมื่อโฟลเดอร์ทำงานมีโครง `My AI Workflow/` หรือผู้ใช้พูดถึง Source, ต้นฉบับ, ยอดรวม, สูตร, QA อ่านหลัง Recon แล้วทำตามทั้ง SKILL.md และไฟล์นี้

## กติกาเพิ่มเติม

1. ห้ามเขียนทับ เปลี่ยนชื่อ ย้าย หรือลบไฟล์ใน `01-input/`
2. สร้างไฟล์ใหม่ใน `03-output/` เท่านั้น ถ้าชื่อซ้ำให้เติมวันที่ เวลา หรือ `-v2`
3. ข้อมูลที่ไม่มีใน Source ต้องเขียนว่า `ต้องตรวจ` หรือ `ไม่พบข้อมูล` ห้ามเดา
4. ก่อนจบงาน ตรวจชื่อ วันที่ จำนวนเงิน จำนวนวัน สูตร และยอดรวมกับ Source แล้วบันทึกผลใน `04-review/QA-CHECKLIST.md`
5. ห้ามส่งอีเมล ข้อความ เอกสาร หรือแก้สถานะในระบบภายนอกโดยไม่ได้รับอนุญาตเฉพาะครั้ง

## Recon เพิ่มเติม

ตรวจว่ามีโครงนี้ ถ้าไม่มีให้เสนอสร้างส่วนที่ขาดและขออนุญาตก่อนเขียนไฟล์:

```text
My AI Workflow/
├─ 01-input/
├─ 02-brief/
├─ 03-output/
├─ 04-review/
└─ HOW-TO-RERUN.md
```

รายงานสั้น ๆ ก่อนรอบแรก: พบไฟล์อะไรใน `01-input/`, ไฟล์ใดเป็น Source ของงานนี้, มีไฟล์ใดดูเป็นต้นฉบับจริงที่ยังไม่ได้ทำสำเนา, ผลลัพธ์ใหม่จะบันทึกที่ใด ถ้าผู้ใช้ยังใช้ต้นฉบับโดยตรง ให้หยุดและขอให้ทำสำเนาก่อน

## หัวข้อคำถามเพิ่มเติม

นอกจากหัวข้อมาตรฐาน รอบสัมภาษณ์ต้องครอบคลุม: Source ที่อนุญาตให้อ่าน · สูตร กติกา ช่วงวันที่ หรือสถานะที่ต้องใช้ · รายการที่ AI ห้ามตัดสินใจเอง · ผู้รับผิดชอบอนุมัติก่อนนำไปใช้

## Working Brief เพิ่มเติม

บันทึกที่ `02-brief/WORKING-BRIEF.md` และเพิ่ม section เหล่านี้ใน template มาตรฐาน:

```markdown
## Source
- <ชื่อไฟล์และ Path>

## Rules & Calculations
- <สูตร กติกา วันที่อ้างอิง และสมมติฐานที่ผู้ใช้ยืนยัน>

## Human Review
- <เรื่องที่คนต้องตรวจหรือตัดสินใจ>
```

## ตอนลงมือ (เมื่อผู้ใช้เลือก Continue)

ก่อนทำ: อ่าน Brief ที่ยืนยันแล้ว, อ่านเฉพาะ Source ที่ระบุ, บอกแผนสั้น ๆ และชื่อไฟล์ใหม่ที่จะสร้าง, ยืนยันว่าจะไม่แก้ไฟล์ใน `01-input/`

ระหว่างทำ: เก็บรูปแบบและลำดับคอลัมน์จาก Source เท่าที่จำเป็น, แสดงสูตรสำคัญให้ตรวจได้, อย่าลบแถวที่ผิดปกติ ให้ Flag แทน

## QA และส่งมอบ

บันทึก `04-review/QA-CHECKLIST.md` อย่างน้อย:

```markdown
# QA Checklist

| จุดตรวจ | ผล | หลักฐาน / หมายเหตุ |
|---|---|---|
| ต้นฉบับไม่ถูกเขียนทับ | ผ่าน / ไม่ผ่าน | |
| ชื่อและวันที่ตรง Source | ผ่าน / ไม่ผ่าน / ต้องตรวจ | |
| จำนวนเงินหรือจำนวนวันรวมตรง | ผ่าน / ไม่ผ่าน / ต้องตรวจ | |
| สูตรสำคัญแสดงและคำนวณซ้ำแล้ว | ผ่าน / ไม่ผ่าน / ต้องตรวจ | |
| ข้อมูลที่ขาดถูก Flag ไม่ได้เดา | ผ่าน / ไม่ผ่าน | |
| ผู้รับผิดชอบตรวจและอนุมัติ | รอตรวจ / อนุมัติ | |
```

สรุป 4 ส่วน: ไฟล์ที่อ่าน · ไฟล์ใหม่ที่สร้าง · สูตรหรือกติกาที่ใช้ · รายการที่คนยังต้องตรวจ แล้วเขียน `HOW-TO-RERUN.md` แบบสั้น: ไฟล์ที่ต้องเตรียม สิ่งที่ต้องเปลี่ยนใน Prompt ลำดับการรัน จุดตรวจรับ และสิ่งที่ห้ามทำ

## Definition of Done

- ผลลัพธ์เป็นไฟล์ใหม่ ต้นฉบับไม่เปลี่ยน
- ชื่อ วันที่ จำนวนเงิน จำนวนวัน และสูตรสำคัญตรวจย้อนกลับได้
- ข้อมูลที่ไม่รู้ถูก Flag ไม่ได้แต่งขึ้น
- ผู้ใช้สั่งทำซ้ำหรือแก้ Prompt ได้ด้วยตัวเอง
- มี Source copy, Working Brief, Output, QA Checklist และ HOW-TO-RERUN ครบ

## สัญญาณให้หยุดและถามทันที

ไฟล์ใน `01-input/` อาจเป็นต้นฉบับชุดเดียว · สูตรหรือความหมายรหัสไม่ชัด · ยอดรวมไม่ตรง Source · มีข้อมูลส่วนตัว เลขบัญชี หรือข้อมูลลูกค้าที่ไม่จำเป็นต่อ Output · ผู้ใช้ขอให้ส่งหรือเผยแพร่แต่ยังไม่ระบุผู้อนุมัติ
